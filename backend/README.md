# PlasticNet AI — Inference Backend

FastAPI service that runs the trained segmentation models and replaces
the mocked `runSegmentation()` response in `src/services/api.js` with a
real prediction. Nothing about the frontend changes to use this beyond
the two lines documented in "Frontend integration" below.

## Important: what these models actually do

Every checkpoint in `weights/` was inspected directly (final layer shape
checked against the state dict, not assumed) before this backend was
built. All four are **binary segmentation models**: each pixel is
classified as `Background` or `Plastic`, full stop. None of them
distinguish bottle from wrapper from polythene, because none of them were
trained to.

That means the API returns a real, honest `coveragePercent`, plastic/
background pixel counts, a real mask and overlay image, and a connected-
component count of distinct plastic regions (`objectsFound`). It does
**not** return a real per-category breakdown. The `classes` array in the
response reflects that honestly (`Background` and `Plastic` only) rather
than fabricating six categories the model has no way to actually predict.
If per-category classification is needed later, that requires training a
new multi-class model, this backend doesn't paper over that with fake
numbers.

The `final_int8_model_*.pth` files that were also provided are not used
here. They aren't deployable quantized weights, they're quantization-
aware-training checkpoints (still float32, with extra observer/fake-quant
buffers) that need the exact QAT-prepared module graph they were trained
against to load, which wasn't provided. The plain `best_model_*.pth`
files load cleanly with `strict=True` into their architectures and are
what this backend uses.

## Setup

```bash
cd backend
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Running locally

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

- Health check: `GET http://localhost:8000/api/health`
- Interactive API docs (auto-generated by FastAPI): `http://localhost:8000/docs`
- The model loads once at startup (see the log line `Loading model...`),
  not per request, and a warmup pass runs before the server starts
  accepting traffic so the first real upload isn't the slow one.

CUDA is used automatically if `torch.cuda.is_available()`, otherwise CPU.
No environment-specific code needed either way.

## How to switch models

One line. Either edit `config.py`:

```python
ACTIVE_MODEL = "bisenet"   # was "fastscnn"
```

or set an environment variable, which takes precedence and needs no code
change at all:

```bash
PLASTICNET_ACTIVE_MODEL=bisenet uvicorn app:app --host 0.0.0.0 --port 8000
```

Valid values: `fastscnn`, `mobilenet`, `bisenet`, `enet` — see
`MODEL_REGISTRY` in `config.py`. Each entry was verified against its
checkpoint (see "What these models actually do" above); adding a new
model means adding one new entry there, nothing else.

Measured on CPU, in this environment, single 720×1280 inference after
warmup:

| Model | Weights size | ~Inference time |
|---|---|---|
| FastSCNN | 4.7 MB | ~0.1–0.9s |
| MobileNetV2Seg | 53.7 MB | ~0.6s |
| BiSeNetV2 | 20 MB | ~0.8–2s |
| ENet | 1.65 MB | ~3.7s cold, faster warm |

FastSCNN is the current default: fastest, smallest, and the accuracy
tradeoff against the others hasn't been benchmarked here (no labeled test
set was provided, only weights) so "smallest quality/speed tradeoff" is
a reasonable default, not a proven best.

## API

### `POST /api/segmentation/run`

Multipart form upload, field name `file`. Accepts JPG, PNG, WEBP.

```bash
curl -X POST -F "file=@photo.jpg" http://localhost:8000/api/segmentation/run
```

Response `200`:

```json
{
  "success": true,
  "jobId": "JOB-49bdbd08",
  "status": "complete",
  "mode": "segmentation",
  "filename": "photo.jpg",
  "model": "Fast-SCNN",
  "coveragePercent": 6.42,
  "plasticPixels": 20512,
  "backgroundPixels": 241632,
  "totalPixels": 262144,
  "objectsFound": 4,
  "largestRegionPixels": 8210,
  "processingTime": "0.91 sec",
  "imageWidth": 960,
  "imageHeight": 640,
  "maskUrl": "/outputs/JOB-49bdbd08_mask.png",
  "overlayUrl": "/outputs/JOB-49bdbd08_overlay.png",
  "classes": [
    { "name": "Background", "pixels": 241632, "percentage": 92.17, "colorHex": "#000000" },
    { "name": "Plastic", "pixels": 20512, "percentage": 7.83, "colorHex": "#C0392B" }
  ],
  "note": "This model performs binary plastic-vs-background segmentation. Per-category breakdown (bottle, cap, wrapper, polythene, shoe, foam) requires a multi-class model, which is not yet trained."
}
```

`objectsFound` / `largestRegionPixels` come from connected-component
labelling of the binary mask (distinct contiguous plastic regions), not
from per-instance object detection, there's no detection model in this
project yet.

Error responses (`400`/`413`/`503`/`500`) all have the shape
`{"detail": "human readable message"}`, which is what FastAPI's
`HTTPException` produces natively and is safe to show directly in the UI.

### `GET /api/segmentation/models`

Lists every model in the registry and which one is currently active.
Not called by the frontend today, useful for debugging deployments.

### `GET /api/health`

`{"status": "ok", "activeModel": "fastscnn", "modelLoaded": true}`

## Frontend integration

`src/services/api.js` already has everything it needs: a `USE_MOCK` flag
and an axios client pointed at `VITE_API_BASE_URL`. Nothing in that file
needs to change. To go live:

1. Deploy this backend somewhere it stays running (see "Deployment" below,
   GitHub Pages cannot run this, it's static hosting only).
2. Set `VITE_API_BASE_URL` to that backend's URL (must end in `/api`,
   e.g. `https://your-backend.example.com/api`) wherever the frontend is
   built/deployed from.
3. Flip `USE_MOCK = false` in `src/services/api.js`.
4. Add the deployed frontend's origin to `CORS_ORIGINS` in
   `backend/settings.py` (or the `PLASTICNET_CORS_ORIGINS` env var) if
   it's not `http://localhost:5173` or the existing GitHub Pages URL,
   both of which are already allowed.

Two small, necessary exceptions to "don't touch components": in
`Segmentation.jsx` and `CitizenReport.jsx`, the code that used to
unconditionally overwrite `coveragePercent` / `objectsFound` /
`processingTime` with `Math.random()` now uses the real value from the
API response when present (`job.coveragePercent ?? Math.random()...`),
falling back to the exact same mock behaviour when it's not. Nothing
else in either file changed. Without this, a working backend would have
no visible effect on the UI at all, since those three lines discarded
whatever the API returned and replaced it with noise regardless.

## Deployment

GitHub Pages only serves static files, it cannot run this. Options that
can run a FastAPI process: Render, Railway, Fly.io, a HuggingFace Space
(Docker SDK), or any VM. A minimal `Dockerfile` isn't included yet since
it wasn't clear which target you'd deploy to, ask and one can be added
for whichever platform you pick.

Whatever you use, give it at least 1–2GB RAM (MobileNetV2Seg and torch
itself have a meaningful base memory footprint) and expect a slow first
request after any cold start / scale-from-zero, mitigated but not
eliminated by the warmup pass at startup.

## Folder structure

```
backend/
  app.py                        FastAPI app, CORS, static /outputs mount, startup warmup
  config.py                     MODEL_REGISTRY + ACTIVE_MODEL, class names/colors, normalization
  settings.py                   upload limits, CORS origins, output retention
  schemas.py                    Pydantic response models
  routes/
    predict.py                  POST /segmentation/run, GET /segmentation/models
  services/
    model_loader.py             loads + caches the active model once, device auto-detect
    segmentation_service.py     orchestrates one prediction end to end
    preprocess.py                validate upload, resize, normalize, to-tensor
    postprocess.py               argmax mask, resize to original resolution, statistics
    image_utils.py               colour mask, transparent overlay, output cleanup
  models/                       copies of the provided architecture files (enet, bisenet2,
                                 mobilenet, fastscnn) — unmodified except BiSeNetV2's network
                                 backbone download is bypassed in model_loader, not here
  weights/                      best_model_*.pth (the four verified, loadable checkpoints)
  outputs/                      generated mask/overlay PNGs, served at /outputs, auto-cleaned
  temp/                         reserved for future use (currently unused, processing is in-memory)
  logs/                         backend.log
  requirements.txt
```
